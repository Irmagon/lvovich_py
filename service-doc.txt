===============================================================================
  Lvovich — склонение русских ФИО, городов и организаций (Python / FastAPI)
===============================================================================

  HTTP-сервис склонения русских фамилий, имён, отчеств, названий городов и
  организаций по падежам. Python-порт библиотеки nodkz/lvovich.

  Технологии: Python 3, FastAPI, uvicorn. Точка входа — main.py.
  Адрес и порт по умолчанию — http://0.0.0.0:3000.

===============================================================================
  КОНФИГУРАЦИЯ (config.ini)
===============================================================================

  [server]
  address = 0.0.0.0     ; адрес прослушивания
  port = 3000           ; порт
  swagger = true        ; включить автодокументацию Swagger UI (/api-docs)

  [auth]
  token =               ; пусто = авторизация выключена; иначе Bearer-токен
  allowed_ips = 127.0.0.1, ::1   ; список разрешённых IP через запятую, пусто = все

  [logging]
  enabled = true        ; вести ли лог запросов в server.log (true/false)
  mode = async          ; режим записи: async (по умолч.) или sync
  flush_ms = 50         ; интервал сброса буфера на диск, мс (только async)
  buffer_kb = 64        ; порог объёма буфера для внепланового сброса, КБ (async)

  Параметры (чтение — fioincline/config.py):
    server.address   - адрес прослушивания
    server.port      - порт
    server.swagger   - true/false — показывать автодокументацию
                       (/api-docs, /openapi.json, /redoc)
    auth.token       - Bearer-токен; пусто = авторизация отключена
    auth.allowed_ips - список разрешённых IP
    logging.enabled  - true/false — вести server.log;
                        false - файл server.log не создаётся, запросы не пишутся
    logging.mode     - async (по умолч.) или sync
    logging.flush_ms - интервал сброса буфера (только async)
    logging.buffer_kb - порог объёма буфера, при превышении - внеплановый сброс

===============================================================================
  АВТОРИЗАЦИЯ И ОГРАНИЧЕНИЕ ПО IP
===============================================================================

  Если в config.ini задан token, все запросы к /api/* и /soap
  должны содержать заголовок "Authorization: Bearer <token>".
  Иначе возвращается 401 {"error":"Unauthorized"}.

  Если задан allowed_ips, запросы разрешены только с указанных IP.
  Иначе возвращается 403 {"error":"Forbidden"}.

===============================================================================
  ЛОГИРОВАНИЕ
===============================================================================

  Каждый REST-запрос к /api/* пишется в server.log в формате:

    [YYYY-MM-DD HH:MM:SS.mmm] <IP клиента> <METHOD> <path> - <body>

  Режимы:
    async (по умолчанию) - строка добавляется в in-memory буфер, фоновая
      нить сбрасывает его на диск раз в flush_ms или при превышении buffer_kb;
    sync - прямая запись на диск на каждый вызов.

  При logging.enabled = false логгер полностью отключается: файл server.log
  не создаётся и обработка запросов ускоряется (нет буферизации и диска).

===============================================================================
  REST API
===============================================================================

  Все REST-эндпоинты: метод POST, Content-Type: application/json.
  Возвращают JSON. Порядок ключей в ответе фиксированный (см. примеры).

  -----------------------------------------------------------------------------
  1. POST /api/incline - склонение ФИО по падежам
  -----------------------------------------------------------------------------
  Тело (JSON):
    SurName    - string, необяз. - Фамилия
    FirstName  - string, необяз. - Имя
    SecondName - string, необяз. - Отчество
    declension - string, необяз. - Падеж: nominative, genitive, dative,
                                    accusative, instrumental, prepositional
    format     - string, необяз. - "full" (по умолч.) или "initials"

  Пример (full, dative):
    > {"SurName":"Иванов","FirstName":"Иван","SecondName":"Иванович","declension":"dative"}
    < {"SurName":"Иванову","FirstName":"Ивану","SecondName":"Ивановичу","gender":"male"}

  Пример (initials, genitive):
    > {"SurName":"Петров","FirstName":"Пётр","SecondName":"Петрович",
       "declension":"genitive","format":"initials"}
    < {"SurName":"Петрова","initials":"П.П."}

  -----------------------------------------------------------------------------
  2. POST /api/gender - определение пола по ФИО
  -----------------------------------------------------------------------------
  Тело (JSON): {"SurName":"Смирнова","FirstName":"Анна"}
  Ответ:       {"gender":"female"}

  -----------------------------------------------------------------------------
  3. POST /api/city/in - город в предложном падеже ("в Москве")
  -----------------------------------------------------------------------------
  Тело (JSON): {"name":"Москва","gender":"female"}
  Ответ:       {"name":"Москве"}

  -----------------------------------------------------------------------------
  4. POST /api/city/from - город в родительном падеже ("из Москвы")
  -----------------------------------------------------------------------------
  Тело (JSON): {"name":"Москва","gender":"female"}
  Ответ:       {"name":"Москвы"}

  -----------------------------------------------------------------------------
  5. POST /api/city/to - город в винительном падеже ("в Москву")
  -----------------------------------------------------------------------------
  Тело (JSON): {"name":"Москва"}
  Ответ:       {"name":"Москву"}

  -----------------------------------------------------------------------------
  6. POST /api/org/in - организация в предложном падеже ("в «Ромашке»")
  -----------------------------------------------------------------------------
  Тело (JSON): {"name":"ООО «Ромашка»"}
  Ответ:       {"name":"ООО «Ромашке»"}

  -----------------------------------------------------------------------------
  7. POST /api/org/from - организация в родительном падеже ("из «Ромашки»")
  -----------------------------------------------------------------------------
  Тело (JSON): {"name":"ООО «Ромашка»"}
  Ответ:       {"name":"ООО «Ромашки»"}

  -----------------------------------------------------------------------------
  8. POST /api/org/to - организация в винительном падеже ("в «Ромашку»")
  -----------------------------------------------------------------------------
  Тело (JSON): {"name":"ООО «Ромашка»"}
  Ответ:       {"name":"ООО «Ромашку»"}

  Примечание: родовое слово (ООО, ПАО, банк, компания и т.п.) не склоняется —
  склоняется только значимая часть названия. Аббревиатуры (МТС, РЖД и т.п.)
  не склоняются вовсе.

===============================================================================
  SOAP-СЕРВИС
===============================================================================

  SOAP-сервис доступен по адресу /soap (метод POST). WSDL-схема — /wsdl
  (или GET /soap?wsdl). Пространство имён: urn:LvovichService.

  Поддерживаемые операции:
    Incline    - склонение ФИО
    GetGender  - определение пола
    CityIn     - город предложный
    CityFrom   - город родительный
    CityTo     - город винительный
    OrgIn      - организация предложный
    OrgFrom    - организация родительный
    OrgTo      - организация винительный

  Общий формат конверта:
    <?xml version="1.0" encoding="UTF-8"?>
    <soap:Envelope xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/">
      <soap:Body>
        <Incline xmlns="urn:LvovichService">...</Incline>
      </soap:Body>
    </soap:Envelope>

  1. Incline - склонение ФИО
  --------------------------------------------------------------------------------
  Параметры:
    LastName   - string, необяз. - Фамилия
    FirstName  - string, необяз. - Имя
    MiddleName - string, необяз. - Отчество
    Declension - string, необяз. - Падеж (см. ниже)
    Format     - string, необяз. - "full" (по умолч.) или "initials"
  Ответ:
    LastName, FirstName, MiddleName, Gender (в формате "full")
    LastName, Initials (в формате "initials")

  Падежи (Declension): nominative, genitive, dative, accusative,
    instrumental, prepositional.

  Пример запроса (full, dative):
    <?xml version="1.0" encoding="UTF-8"?>
    <soap:Envelope xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/">
      <soap:Body>
        <Incline xmlns="urn:LvovichService">
          <LastName>Иванов</LastName>
          <FirstName>Иван</FirstName>
          <MiddleName>Иванович</MiddleName>
          <Declension>dative</Declension>
        </Incline>
      </soap:Body>
    </soap:Envelope>
  Пример ответа:
    <LastName>Иванову</LastName>
    <FirstName>Ивану</FirstName>
    <MiddleName>Ивановичу</MiddleName>
    <Gender>male</Gender>

  Пример запроса (initials, genitive):
    <?xml version="1.0" encoding="UTF-8"?>
    <soap:Envelope xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/">
      <soap:Body>
        <Incline xmlns="urn:LvovichService">
          <LastName>Петров</LastName>
          <FirstName>Пётр</FirstName>
          <MiddleName>Петрович</MiddleName>
          <Declension>genitive</Declension>
          <Format>initials</Format>
        </Incline>
      </soap:Body>
    </soap:Envelope>
  Пример ответа:
    <LastName>Петрова</LastName>
    <Initials>П.П.</Initials>

  2. GetGender - определение пола по ФИО
  --------------------------------------------------------------------------------
  Параметры:
    LastName   - string, необяз. - Фамилия
    FirstName  - string, необяз. - Имя
    MiddleName - string, необяз. - Отчество
  Ответ:
    Gender - string - "male", "female" или "androgynous"

  3. CityIn - город в предложном падеже
  --------------------------------------------------------------------------------
  Параметры: Name (string, обязат.), Gender (string, необяз.)
  Ответ:     Name
  Пример:
    <CityIn xmlns="urn:LvovichService"><Name>Москва</Name></CityIn>
    <CityInResponse xmlns="urn:LvovichService"><Name>Москве</Name></CityInResponse>

  4. CityFrom - город в родительном падеже
  --------------------------------------------------------------------------------
  Параметры: Name (string, обязат.), Gender (string, необяз.)
  Ответ:     Name
  Пример:
    <CityFrom xmlns="urn:LvovichService"><Name>Москва</Name></CityFrom>
    <CityFromResponse xmlns="urn:LvovichService"><Name>Москвы</Name></CityFromResponse>

  5. CityTo - город в винительном падеже
  --------------------------------------------------------------------------------
  Параметры: Name (string, обязат.)
  Ответ:     Name
  Пример:
    <CityTo xmlns="urn:LvovichService"><Name>Москва</Name></CityTo>
    <CityToResponse xmlns="urn:LvovichService"><Name>Москву</Name></CityToResponse>

  6. OrgIn - организация в предложном падеже
  --------------------------------------------------------------------------------
  Параметры: Name (string, обязат.)
  Ответ:     Name
  Пример:
    <OrgIn xmlns="urn:LvovichService"><Name>ООО «Ромашка»</Name></OrgIn>
    <OrgInResponse xmlns="urn:LvovichService"><Name>ООО «Ромашке»</Name></OrgInResponse>

  7. OrgFrom - организация в родительном падеже
  --------------------------------------------------------------------------------
  Параметры: Name (string, обязат.)
  Ответ:     Name
  Пример:
    <OrgFrom xmlns="urn:LvovichService"><Name>ООО «Ромашка»</Name></OrgFrom>
    <OrgFromResponse xmlns="urn:LvovichService"><Name>ООО «Ромашки»</Name></OrgFromResponse>

  8. OrgTo - организация в винительном падеже
  --------------------------------------------------------------------------------
  Параметры: Name (string, обязат.)
  Ответ:     Name
  Пример:
    <OrgTo xmlns="urn:LvovichService"><Name>ООО «Ромашка»</Name></OrgTo>
    <OrgToResponse xmlns="urn:LvovichService"><Name>ООО «Ромашку»</Name></OrgToResponse>

===============================================================================
  КОНКУРЕНТНОСТЬ
===============================================================================

  - Сервер обрабатывает входящие соединения через ASGI-сервер uvicorn.
    Синхронные маршруты FastAPI выполняются в пуле потоков, что позволяет
    обрабатывать конкурентные запросы параллельно (в пределах потоков пула).
  - Ядро склонения (lvovich) stateless: чистые функции без общего состояния,
    поэтому обработчики не блокируют друг друга.
  - Единственное общее состояние — логгер (fioincline/logger.py).
    При enabled=false логгер полностью отключается (log() ничего не делает,
    файл server.log не создаётся), и общее состояние исчезает вовсе.

  Логгер в режиме async (по умолчанию):
    - log() добавляет строку в in-memory буфер под короткой блокировкой,
      без диска;
    - фоновая нить-флашер сбрасывает буфер на диск пакетом раз в
      flush_ms (по умолч. 50 мс) или по достижении buffer_kb (по умолч. 64 КБ);
    - порядок строк и логика lastIP сохраняются; close()/flush() на выходе
      из процесса (см. main.py).

  Это убирает диск из горячего пути запроса. Остаточный риск: потеря последних
  строк лога при аварийном завершении (kill -9) в пределах интервала флаша
  (~50 мс). При режиме sync лог пишется на диск синхронно на каждый вызов.
