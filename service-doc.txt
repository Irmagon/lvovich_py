================================================================================
  Lvovich — склонение русских ФИО, городов и организаций
================================================================================

  SOAP:        http://localhost:3000/soap
  WSDL:        http://localhost:3000/wsdl
  REST:        http://localhost:3000/api/*
  Swagger UI:  http://localhost:3000/api-docs
  Запуск:      go run ./cmd/server   (или собранный бинарь fioincline-server.exe)
  Тесты:       run-tests.cmd  (сборка + go test ./... с логом в test-output\)


================================================================================
  КОНФИГУРАЦИЯ (config.ini)
================================================================================

  Файл config.ini в корне проекта:

    [server]
    address = 0.0.0.0
    port = 3000
    swagger = true

    [auth]
    token = mysecret
    ; список разрешённых IP через запятую, пусто = все
    allowed_ips = 127.0.0.1, ::1

    [logging]
    ; вести ли лог запросов в server.log (true/false)
    enabled = true
    ; режим записи лога: async (по умолч.) или sync
    mode = async
    ; интервал сброса буфера на диск, мс (только async)
    flush_ms = 50
    ; порог объёма буфера для внепланового сброса, КБ (только async)
    buffer_kb = 64

  Параметры:
    server.address    - адрес для привязки (по умолч. 0.0.0.0)
    server.port       - порт HTTP-сервера (по умолч. 3000)
    server.swagger    - включить/отключить Swagger UI (по умолч. true)
    auth.token        - токен авторизации (пусто = отключена)
    auth.allowed_ips  - список разрешённых IP через запятую (пусто = все)
    logging.enabled   - включить/отключить логирование запросов (по умолч. true);
                        false - файл server.log не создаётся, запросы не пишутся
    logging.mode      - async - буфер в памяти + фоновый сброс на диск;
                        sync - прямая запись на диск на каждый вызов (медленно)
    logging.flush_ms  - период сброса буфера (по умолч. 50 мс)
    logging.buffer_kb - порог объёма буфера, при превышении - внеплановый сброс
                        (по умолч. 64 КБ)


================================================================================
  АВТОРИЗАЦИЯ И ОГРАНИЧЕНИЕ ПО IP
================================================================================

  Если в config.ini задан token, все запросы к /api/* и /soap
  требуют заголовок:

    Authorization: Bearer <token>

  Если задан allowed_ips, запросы разрешены только с указанных IP
  (работает независимо от токена).
  WSDL (/wsdl) доступен без ограничений.
  Swagger UI (/api-docs) доступен только если в config.ini указано swagger = true.

================================================================================
  REST API
================================================================================

  Все REST-методы требуют заголовок Authorization: Bearer <token>
  (если токен задан в config.ini).

  Ошибки REST:
    401 - отсутствует или неверный токен
    403 - IP не входит в allowed_ips


  POST /api/incline — склонение ФИО
  --------------------------------------------------------------------------------
    Body (JSON):
      FirstName  - string, необяз. - Имя
      SurName    - string, необяз. - Фамилия
      SecondName - string, необяз. - Отчество
      declension - string, необяз. - Падеж: nominative, genitive, dative,
                                      accusative, instrumental, prepositional)
      format     - string, необяз. - "full" (по умолч.) или "initials"

    Пример (format=full):
      > POST /api/incline
      > Authorization: Bearer mysecret
      > {"SurName":"Иванов","FirstName":"Иван","SecondName":"Иванович","declension":"dative"}
      < {"SurName":"Иванову","FirstName":"Ивану","SecondName":"Ивановичу","gender":"male"}

    Пример (format=initials):
      > Authorization: Bearer mysecret
      > {"SurName":"Петров","FirstName":"Пётр","SecondName":"Петрович",
         "declension":"genitive","format":"initials"}
      < {"SurName":"Петрова","initials":"П.П."}


  POST /api/gender — определение пола
  --------------------------------------------------------------------------------
    Body (JSON): {"SurName":"Смирнова","FirstName":"Анна"}
    Ответ:       {"gender":"female"}


  POST /api/city/in — город в предложном падеже (в каком?)
  --------------------------------------------------------------------------------
    Body (JSON): {"name":"Москва","gender":"female"}
    Ответ:       {"name":"Москве"}


  POST /api/city/from — город в родительном падеже (из какого?)
  --------------------------------------------------------------------------------
    Body (JSON): {"name":"Москва"}
    Ответ:       {"name":"Москвы"}


  POST /api/city/to — город в винительном падеже (в какой?)
  --------------------------------------------------------------------------------
    Body (JSON): {"name":"Москва"}
Ответ:       {"name":"Москву"}


  POST /api/org/in — организация в предложном падеже (в какой?)
  --------------------------------------------------------------------------------
    Body (JSON): {"name":"ООО «Ромашка»"}
    Ответ:       {"name":"ООО «Ромашке»"}


  POST /api/org/from — организация в родительном падеже (из какой?)
  --------------------------------------------------------------------------------
    Body (JSON): {"name":"ООО «Ромашка»"}
    Ответ:       {"name":"ООО «Ромашки»"}


  POST /api/org/to — организация в винительном падеже (в какую?)
  --------------------------------------------------------------------------------
    Body (JSON): {"name":"ООО «Ромашка»"}
    Ответ:       {"name":"ООО «Ромашку»"}

  Примечание: родовое слово (ООО, ПАО, банк, компания и т.п.) не склоняется —
  склоняется только значимая часть названия. Аббревиатуры (МТС, РЖД и т.п.)
  остаются неизменными. Кавычки в названии сохраняются как на входе.

1. Incline - склонение ФИО по падежам
--------------------------------------------------------------------------------

  Параметры:
    LastName   - string, необяз. - Фамилия
    FirstName  - string, необяз. - Имя
    MiddleName - string, необяз. - Отчество
    Declension - string, необяз. - Падеж (см. ниже)
    Format     - string, необяз. - "full" (по умолч.) или "initials"

  Падежи (Declension):
    nominative     - Именительный  (Иванов)
    genitive       - Родительный   (Иванова)
    dative         - Дательный     (Иванову)
    accusative     - Винительный   (Иванова)
    instrumental   - Творительный  (Ивановым)
    prepositional  - Предложный    (Иванове)

  Ответ (Format=full):
    FirstName  - string - Имя в нужном падеже
    LastName   - string - Фамилия в нужном падеже
    MiddleName - string - Отчество в нужном падеже
    Gender     - string - "male", "female" или "androgynous"

  Ответ (Format=initials):
    LastName   - string - Фамилия в нужном падеже
    Initials   - string - Инициалы вида "И." или "И.И."

  Пример запроса (full, dative):
    <?xml version="1.0" encoding="UTF-8"?>
    <soap:Envelope xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/">
      <soap:Body>
        <Incline xmlns="urn:LvovichService">
          <LastName>Иванов</LastName>
          <FirstName>Иван</FirstName>
          <MiddleName>Иванович</MiddleName>
          <Declension>dative</Declension>
        </Incline>
      </soap:Body>
    </soap:Envelope>

  Пример ответа:
    <LastName>Иванову</LastName>
    <FirstName>Ивану</FirstName>
    <MiddleName>Ивановичу</MiddleName>
    <Gender>male</Gender>

  Пример запроса (initials, genitive):
    <?xml version="1.0" encoding="UTF-8"?>
    <soap:Envelope xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/">
      <soap:Body>
        <Incline xmlns="urn:LvovichService">
          <LastName>Петров</LastName>
          <FirstName>Пётр</FirstName>
          <MiddleName>Петрович</MiddleName>
          <Declension>genitive</Declension>
          <Format>initials</Format>
        </Incline>
      </soap:Body>
    </soap:Envelope>

  Пример ответа:
    <LastName>Петрова</LastName>
    <Initials>П.П.</Initials>

================================================================================
  КОНКУРЕНТНОСТЬ
================================================================================

  - Сервер обрабатывает входящие соединения в отдельных горутинах
    (net/http): каждый запрос — своя горутина, планируемых рантаймом
    поверх потоков ОС. Явной многопоточности в коде приложения нет.
  - Ядро склонения (lvovich) stateless: чистые функции без общего
    состояния, поэтому хендлеры не блокируют друг друга.
  - Единственное общее состояние — логгер (internal/server/logging.go).
    При enabled=false логгер полностью отключается (Log() ничего не делает,
    файл server.log не создаётся), и общее состояние исчезает вовсе.

  Логгер в режиме async (по умолчанию):
    - Log() добавляет строку в in-memory буфер под коротким mutex, без диска;
    - фоновая горутина-флашер сбрасывает буфер на диск пакетом раз в
      flush_ms (по умолч. 50 мс) или по достижении buffer_kb (по умолч. 64 КБ);
    - порядок строк и логика lastIP сохраняются; Close()/Flush() на выходе
      из процесса (см. cmd/server/main.go: обработка Ctrl+C/SIGTERM).

  Это убирает диск из горячего пути запроса: параллельные бенчмарки
  масштабируются (см. таблицу выше). Остаточный риск: потеря последних
  строк лога при аварийном завершении (kill -9) в пределах интервала флаша
  (~50 мс). При режиме sync лог пишется на диск синхронно на каждый вызов —
  ~0.22–0.44 мс/оп без роста параллели (см. таблицу выше).
